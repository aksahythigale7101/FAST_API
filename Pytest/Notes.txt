## 1. What is Pytest?

**Pytest** is a Python testing framework used to automatically test and verify Python code.

### Marathi

आपण application मध्ये code लिहितो. तो code manually check करण्याऐवजी **automatically verify/test** करण्यासाठी Pytest वापरतो.

Example:

```python
def add(a, b):
    return a + b

```

Test:

```python
def test_add():
    assert add(2, 3) == 5

```

---

# 2. What is `assert`?

`assert` वापरून आपण **actual result expected result सारखा आहे का** ते verify करतो.

### Simple meaning

> `assert` condition True असली पाहिजे.
> Condition False असेल तर test fail होतो.

Example:

```python
def test_add():
    result = 10 + 20

    assert result == 30

```

इथे:

```text
result = 30
expected = 30

```

म्हणून test PASS.

Common test function naming:


# 6. What is `-s`?

`-s` pytest चा **stdout capturing disable** करतो.

सोप्या भाषेत:

> Test मध्ये `print()` केले असेल आणि ते terminal मध्ये पाहायचे असेल तर `-s` वापरतो.

Example:

```python
def test_add():
    result = 10 + 20
    print("Result:", result)

    assert result == 30

```

Run:

```bash
pytest -s

```

किंवा:

```bash
pytest -v -s

```

### Important

`-s` म्हणजे फक्त `print()` output पाहण्यासाठी उपयोगी आहे.

```bash
pytest test_math.py::test_add -v -s

```

# 7. What is `pytest.raises()`?

`pytest.raises()` वापरून आपण **specific exception expected आहे** हे verify करतो.

Meaning:

> "या code block मध्ये हा specific exception येणे expected आहे."

Example:

```python
import pytest


def divide(a, b):
    return a / b


def test_divide_by_zero():
    with pytest.raises(ZeroDivisionError):
        divide(10, 0)

```

इथे आपण expect करतो:

```text
divide(10, 0)
        ↓
ZeroDivisionError

```

Exception आली → PASS

Exception आली नाही → FAIL

# 8. Fixture म्हणजे काय?

**Fixture** म्हणजे test साठी लागणारा reusable setup/data/resource.

Example:

```python
import pytest


@pytest.fixture
def user():
    return {
        "name": "Akshay",
        "age": 25
    }


def test_user(user):
    assert user["name"] == "Akshay"

```

इथे:

```python
@pytest.fixture
def user():

```

हा fixture आहे.

Test function मध्ये:

```python
def test_user(user):

```

`user` fixture automatically मिळतो.

### Simple definition

> Fixture is a reusable piece of test setup/data that pytest provides to test functions.

---

# 9. Fixture Scope म्हणजे काय?

**Scope ठरवतो की fixture किती वेळा create होईल आणि किती tests मध्ये reuse होईल.**

Default scope:

```text
function

```

---

## Fixture Scopes

| Scope | When created | Typical use |
|---|---|---|
| `function` | For every test function | Fresh test data |
| `class` | Once per test class | Shared class setup |
| `module` | Once per test module/file | Shared module resource |
| `package` | Once per package | Package-level resource |
| `session` | Once per entire pytest run | Heavy resources |

--------------------------------- | ------------------------------ | ---------------------- |
| function                             | प्रत्येक test function साठी    | Fresh test data        |
| class                                | प्रत्येक test class साठी       | Class-level setup      |
| module                               | प्रत्येक test file/module साठी | Shared resource        |
| package                              | प्रत्येक package साठी          | Package-level resource |
| session                              | संपूर्ण pytest run मध्ये एकदा  | Heavy resources        |

---

## 9.1 Function Scope

```python
@pytest.fixture(scope="function")
def data():
    return "Hello"

```

हा default scope आहे.

```text
test_1 → fixture create
test_2 → fixture create
test_3 → fixture create

```

प्रत्येक test ला नवीन fixture.

---

## 9.2 Class Scope

```python
@pytest.fixture(scope="class")
def data():
    return "Hello"

```

एका test class मधील tests साठी fixture एकदा create होतो.

---

## 9.3 Module Scope

```python
@pytest.fixture(scope="module")
def data():
    return "Hello"

```

एका Python test file/module साठी fixture एकदा create होतो.

---

## 9.4 Package Scope

```python
@pytest.fixture(scope="package")
def data():
    return "Hello"

```

एका package साठी fixture तयार होतो.

हा scope तुलनेने कमी वापरला जातो.

---

## 9.5 Session Scope

```python
@pytest.fixture(scope="session")
def data():
    return "Hello"

```

संपूर्ण pytest execution मध्ये fixture एकदाच तयार होतो.

उदा.:

```text
pytest run
   ↓
session fixture create
   ↓
all tests
   ↓
pytest run समाप्त

```

Heavy resources साठी useful:

- Database setup
- Test server
- Expensive initialization
- Shared configuration

# 10. Parametrization म्हणजे काय?

**Parametrization** म्हणजे same test वेगवेगळ्या input values सोबत अनेक वेळा run करणे.

Pytest मध्ये:

```python
@pytest.mark.parametrize()

```

Example:

```python
import pytest


def add(a, b):
    return a + b


@pytest.mark.parametrize(
    "a,b,expected",
    [
        (2, 3, 5),
        (10, 20, 30),
        (5, 5, 10)
    ]
)
def test_add(a, b, expected):
    assert add(a, b) == expected

```

इथे एकच test तीन different data sets सोबत execute होईल.

### Advantage

Repeated test code लिहावे लागत नाही.

# 11. What is `conftest.py`?

`conftest.py` ही Pytest ची **special file** आहे.

यामध्ये commonly shared fixtures ठेवतो.

Pytest `conftest.py` automatically discover करू शकतो.

Example structure:

```text
app/
│
├── conftest.py
│
├── test_user.py
├── test_product.py
└── test_order.py

```

`conftest.py`:

```python
import pytest


@pytest.fixture
def user():
    return {
        "name": "Akshay"
    }

```

नंतर test मध्ये fixture वापरू शकतो:

```python
def test_user(user):
    assert user["name"] == "Akshay"

```

### Interview answer

> `conftest.py` is a special pytest file used to define shared fixtures and pytest configuration that can be automatically discovered by tests.

# 13. Unit Test vs Integration Test

हा एक important interview topic आहे.

## Unit Test

Unit test मध्ये application चा **smallest testable unit** independently test करतो.

Example:

```python
def add(a, b):
    return a + b

```

Test:

```python
def test_add():
    assert add(2, 3) == 5

```

इथे फक्त `add()` function test केला आहे.

### Simple meaning

> Unit Test = एका छोट्या component/function ला isolated पद्धतीने test करणे.

---

# 14. Integration Test

Integration test मध्ये **दोन किंवा अधिक components एकत्र properly काम करत आहेत का** ते test करतो.

उदाहरण:

```text
FastAPI endpoint
       ↓
Service
       ↓
Database

```

हे components एकत्र test करणे म्हणजे integration testing.

### Important Correction

तुमच्या original notes मध्ये:

```text
def test_add():
    assert add(2, 3) == 5

```

हे **Integration Test नाही**.

हे **Unit Test** आहे.

### Interview definition

> Integration testing verifies that multiple components or systems work correctly together.

# 15. Mocking म्हणजे काय?

Testing करताना external dependency प्रत्येक वेळेस real वापरणे योग्य नसते.

उदाहरण:

```text
Your Application
      ↓
Payment API
      ↓
Real Payment System

```

Test करताना प्रत्येक वेळी real payment API call केला तर:

- Test slow होऊ शकतो
- Internet dependency येते
- पैसे actually charge होण्याचा risk असतो
- External service unavailable असू शकते

म्हणून आपण **fake/mock dependency** वापरतो.

### Definition

> Mocking is the technique of replacing a real dependency with a controlled fake object during testing.

---

# 16. Why Do We Mock External APIs?

External APIs mock करण्याचे कारण:

```text
Fast
Deterministic
Isolated
Independent
Safe

```

Interview answer:

> We mock external APIs to make tests fast, deterministic, isolated, and independent of external services.

# 18. MagicMock

```python
from unittest.mock import MagicMock

```

`MagicMock` हा Mock सारखाच आहे, पण Python च्या **magic/dunder methods** साठी additional support देतो.

उदा.:

```python

__len__
__iter__
__getitem__

```

### Interview answer

> `Mock` provides standard mocking functionality, while `MagicMock` also supports Python magic methods.

# 19. What is `patch()`?

`patch()` वापरून आपण test च्या duration मध्ये एखादा real object temporarily replace करू शकतो.

Example:

```python
from unittest.mock import patch


def get_payment():
    return payment_api.call()


def test_payment():
    with patch("module.payment_api.call") as mock_call:
        mock_call.return_value = "success"

        result = get_payment()

        assert result == "success"

```

### Important

`patch()` permanent replacement करत नाही.

Test संपल्यानंतर original object restore होतो.

### Interview answer

> `patch()` temporarily replaces an object with a mock during a test.

# 23. AAA Pattern

AAA म्हणजे:

```text
A → Arrange
A → Act
A → Assert

```

Testing code organize करण्याचा हा common pattern आहे.

---

## Arrange

Test साठी required data/setup तयार करणे.

```python
a = 10
b = 20

```

---

## Act

Actual function call करणे.

```python
result = add(a, b)

```

---

## Assert

Expected result verify करणे.

```python
assert result == 30

```

Complete example:

```python
def test_add():

    # Arrange
    a = 10
    b = 20

    # Act
    result = add(a, b)

    # Assert
    assert result == 30

```

### Interview answer

> AAA stands for Arrange, Act, and Assert. It is a common pattern for structuring test cases clearly.

# 24. FastAPI TestClient म्हणजे काय?

FastAPI मध्ये endpoint test करण्यासाठी `TestClient` वापरू शकतो.

### Simple meaning

> `TestClient` allows us to send HTTP requests to a FastAPI application from Python test code without manually using Postman.

Example:

```python
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)


def test_root():
    response = client.get("/")

    assert response.status_code == 200

```

इथे:

```python
client.get("/")

```

FastAPI च्या `/` endpoint ला request पाठवतो.

नंतर:

```python
assert response.status_code == 200

```

response verify करतो.

# 🎯 INTERVIEW QUESTIONS — QUICK ANSWERS

### Q1. What is Pytest?

> Pytest is a Python testing framework used to write and execute automated tests.

> `assert` verifies that an expected condition is true. If it is false, the test fails.

### Q3. What is the default fixture scope?

> `function`.

### Q4. What is a fixture?

> A fixture is a reusable test setup or test data provided to test functions.

### Q5. What is parametrization?

> Parametrization allows the same test to run with multiple sets of input data.

### Q6. What is conftest.py?

> `conftest.py` is a special pytest file used for shared fixtures and pytest configuration.

### Q7. What is mocking?

> Mocking replaces a real dependency with a controlled fake object during testing.

### Q8. Why mock external APIs?

> To make tests fast, deterministic, isolated, and independent of external services.

### Q9. Mock vs MagicMock?

> Mock provides standard mocking functionality, while MagicMock additionally supports Python magic methods.

### Q10. What is patch()?

> `patch()` temporarily replaces an object with a mock during a test.

### Q11. Unit vs Integration Test?

> Unit testing tests an individual component independently, while integration testing verifies that multiple components work correctly together.

### Q12. What is TestClient?

> TestClient allows us to test FastAPI endpoints programmatically by sending HTTP requests from Python test code.

### Q13. What is code coverage?

> Code coverage measures how much of the application code is executed by the tests.

### Q14. What is AAA pattern?

> AAA stands for Arrange, Act, Assert and provides a clear structure for writing test cases.
